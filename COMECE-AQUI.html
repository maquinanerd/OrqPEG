Primeiros passos

O caminho mais curto entre abrir esta página e ver o OrqPEG trabalhando.

  1. Confira o ambiente

    Abra a pasta C:\OrqPEG e execute o diagnóstico. Ele verifica sistema, ferramentas, chaves de API no ambiente, schemas, wrappers, porta do painel e locks.

    DIAGNOSTICO.cmd

  2. Cadastre um projeto que já existe

    O OrqPEG nunca copia o seu código: ele passa a orquestrar o repositório onde ele já está.

    CADASTRAR-PROJETO.cmd

  3. Escreva os prompts

    Um arquivo Markdown por unidade de trabalho, em data\projects\<projeto>\prompts\, seguindo o modelo templates\TEMPLATE-PROMPT.md.

  4. Simule antes de executar

    O dry-run descreve o plano inteiro sem alterar absolutamente nada.

    EXECUTAR-DRY-RUN.cmd

  5. Execute e acompanhe pelo painel

    EXECUTAR.cmd
INICIAR-PAINEL.cmd
O que o produto garante
  • Nenhuma API de IA: só os executáveis locais claude e codex.
  • Nenhuma operação destrutiva: não existe push --force, reset --hard, git clean ou branch -D em nenhum caminho de execução.
  • Nenhum merge com uma IA só: são necessárias duas auditorias independentes sobre o mesmo commit.

O Codex CLI não está instalado nesta máquina

Consequência real, sem rodeios: a auditoria dupla fica bloqueada, o gate CODEX_MERGE_APPROVED reprova e nenhum merge automático acontece. Isso é o comportamento correto — o OrqPEG jamais aprova merge com apenas uma IA.

Para desbloquear, instale o Codex CLI e autentique com “Sign in with ChatGPT”. Enquanto isso, use o dry-run ou configure merge.mode como manual e faça o merge você mesmo pelo GitHub, depois de revisar.

Zero API de IA

O OrqPEG usa exclusivamente as suas assinaturas Claude Max e ChatGPT Plus, através dos executáveis locais. Não existe SDK de provedor, requisição a endpoint de API de IA nem leitura do valor de qualquer chave. O ambiente de todo processo filho é sanitizado — apenas a cópia entregue ao processo, nunca o ambiente do seu Windows.

ANTHROPIC_API_KEY      removida do ambiente do processo filho
OPENAI_API_KEY         removida do ambiente do processo filho
CODEX_API_KEY          removida do ambiente do processo filho
ANTHROPIC_AUTH_TOKEN   removida do ambiente do processo filho
OPENAI_API_KEY_PATH    removida do ambiente do processo filho
ANTHROPIC_ADMIN_KEY    removida do ambiente do processo filho

Se alguma dessas variáveis existir na sua sessão, o OrqPEG reporta apenas o nome dela e bloqueia a execução por padrão. O valor nunca é lido, gravado ou impresso.

Caminhos com espaços e acentos funcionam

Um caminho como E:\Meus Projetos\Ação é suportado: todo caminho é composto com as funções de caminho do Node e validado contra escape de diretório.

Worktrees

Com worktree.enabled ligado, cada execução acontece em um worktree dedicado, criado a partir da branch base. Sua cópia principal continua livre e intocada.

Worktree : E:\AI-Worktrees\<projeto>\orqpeg-<projeto>-run-<stamp>
Branch   : orqpeg/<projeto>/run-<stamp>

reuseWhenSafe permite reaproveitar um worktree existente somente quando é seguro. Se não for, a execução falha com mensagem explícita — nunca destruindo trabalho.

Remover o cadastro não apaga o seu código

REMOVER-PROJETO.cmd remove apenas os dados operacionais do OrqPEG (prompts, estado, logs, relatórios). O repositório permanece exatamente como está.

Prompts

Um arquivo Markdown por unidade de trabalho, executado em ordem natural.

C:\OrqPEG\data\projects\<projeto>\prompts\
  01-camada-de-configuracao.md
  02-parser-de-prompts.md
  10-painel-http.md

A ordem vem da ordenação natural do nome do arquivo, então o prefixo numérico define a sequência: 2-x.md roda antes de 10-x.md. O ID declarado dentro do arquivo deve ser igual ao nome do arquivo sem a extensão.

- src/types.ts

- [ ] Todos os itens do escopo estão implementados.
- [ ] Nenhum arquivo fora das áreas permitidas foi alterado.
- [ ] Todos os comandos de teste do projeto passam.

# Restrições

- Não fazer commit, push, merge nem trocar de branch.
- Não remover nem enfraquecer testes.
Commit, push, PR e merge são responsabilidade exclusiva do OrqPEG

O prompt deve proibir explicitamente que a IA faça qualquer uma dessas operações. Se um teste falha, a correção é no código de produção — nunca no teste.

Execução

O ciclo completo, do primeiro prompt até o merge.

EXECUTAR-DRY-RUN.cmd    simula tudo, sem alterar nada
EXECUTAR.cmd            executa de verdade
01Validar
Projeto, prompts, GitHub CLI autenticado e ambiente sem chave de API vazando.
02Preparar worktree
Worktree e branch criados a partir da base, sem tocar na sua árvore principal.
03Executar
O Claude recebe o prompt renderizado e trabalha apenas dentro do worktree.
04Testar
Os comandos de teste do projeto rodam de verdade, com timeout e saída capturada.
05Revisar
O Codex recebe diff, testes e prompt, e devolve um veredito JSON validado por schema.
06Corrigir
Veredito de mudanças gera nova tentativa com as ações exigidas, até o máximo configurado.
07Commitar
Somente após aprovação. Um commit por prompt, com prefixo configurável.
08Push
Apenas para o remoto declarado no projeto. Force push é impossível por design.
09Pull Request
Criada pelo GitHub CLI, opcionalmente como rascunho durante a execução.
10CI
Espera os checks obrigatórios. Check pendente nunca é tratado como aprovação.
11Auditoria do Claude
Somente leitura, sobre o head SHA observado, com saída validada por schema.
12Auditoria do Codex
Somente leitura, sobre exatamente o mesmo commit.
13Consenso
Só existe com as duas aprovações, mesmo SHA e confiança mínima atingida.
14Gates
Os 20 gates são avaliados e registrados com evidência.
15Merge
Squash com verificação do commit exato: o GitHub recusa se o head mudou.

Pausar, retomar e cancelar

PAUSAR.cmd            solicita pausa; nada e apagado
RETOMAR.cmd           continua de onde parou
CANCELAR-ETAPA.cmd    cancelamento seguro
Nada do seu trabalho é descartado
  • A pausa preserva código, worktree, branch, commits e logs.
  • A retomada não reexecuta prompts já aprovados.
  • O cancelamento não executa reset destrutivo, limpeza ou remoção.
  • Ctrl+C encerra os processos filhos e grava o estado antes de sair.

Painel

Interface local para acompanhar projetos, execuções, consenso e diagnóstico.

INICIAR-PAINEL.cmd
ABRIR-PAINEL.cmd
PARAR-PAINEL.cmd

Endereço padrão: http://127.0.0.1:8765.

O painel é local por construção
  • Escuta exclusivamente em 127.0.0.1; qualquer outro host faz o servidor recusar a inicialização.
  • Valida o cabeçalho Host, o que protege contra ataques de DNS rebinding.
  • Serve arquivos estáticos com resolução confinada à pasta pública.

Trocar a porta

Edite config\global.json:

{
  "panel": {
    "host": "127.0.0.1",
    "port": 8790,
    "openBrowserOnStart": true
  }
}

Sem o Codex CLI instalado e autenticado, não existe auditoria do Codex, logo não existe consenso e o merge automático não acontece. Instale o Codex CLI e autentique com “Sign in with ChatGPT” para habilitar a auditoria dupla.

Invalidação de aprovações

Uma aprovação vale para um commit específico, não para a Pull Request. Qualquer commit novo na branch invalida as auditorias existentes, com o motivo registrado no relatório — e a auditoria precisa ser refeita. No momento do merge, o próprio GitHub recusa a operação se o commit tiver mudado.

Idempotência

Uma Pull Request já mergeada nunca é mergeada de novo: o OrqPEG detecta a situação, registra o desvio idempotente e segue em frente sem efeito colateral.

Solução de problemas

Casos reais, com o comando que diagnostica e o que fazer em seguida.

Node.js ausente ou versão antiga

Sintoma: 'node' não é reconhecido como um comando, ou o diagnóstico acusa versão abaixo de 20.

node --version

Instale o Node.js 20 LTS ou superior, feche e reabra o terminal — o caminho das variáveis de ambiente só é relido em uma sessão nova — e rode o diagnóstico de novo.

GitHub CLI não autenticado

Sintoma: falhas ao criar a Pull Request, ler os checks ou executar o merge.

gh auth status
gh auth login
gh auth status --show-scopes

O escopo repo é necessário. Sem isso, a execução roda mas para antes da criação da Pull Request.

Codex CLI ausente

Sintoma: o diagnóstico marca o Codex como indisponível, o gate CODEX_MERGE_APPROVED reprova e o merge não acontece.

Não é defeito: é a regra de nunca aprovar merge com uma IA só, funcionando.

codex --version
DIAGNOSTICO.cmd
RETOMAR.cmd

Enquanto o Codex não estiver disponível, configure merge.mode como manual: o OrqPEG executa, testa, commita, faz push e abre a Pull Request, e você faz o merge pelo GitHub depois de revisar.

Porta 8765 ocupada

Sintoma: o painel não sobe, ou o diagnóstico reporta a porta em uso.

netstat -ano | findstr :8765
tasklist /FI "PID eq 1234"

Se for uma instância antiga do próprio painel, feche a janela dela. Se for outro programa, troque a porta em config\global.json. O host só aceita 127.0.0.1 ou localhost.

Lock abandonado

Sintoma: erro informando que outra execução está em andamento, quando não há nenhuma.

Os locks têm heartbeat. Um lock é considerado abandonado quando o processo dono não existe mais, quando o host não bate, ou quando o heartbeat está parado há mais de 15 minutos — e nesse caso ele é retomado automaticamente.

DIAGNOSTICO.cmd
dir C:\OrqPEG\data\locks

O diagnóstico lista cada lock com identificador de processo, escopo, operação e idade do heartbeat. Confirme que o processo não está mais rodando antes de remover o arquivo de lock correspondente.

Limite de uso da assinatura atingido

Sintoma: a execução para no estado de limite de uso, com a mensagem do CLI registrada nos artefatos.

Nada foi perdido. Espere a janela de uso reabrir e retome. Prompts já aprovados não são reexecutados, porque cada um virou um commit próprio.

RETOMAR.cmd

Se acontecer com frequência, divida o trabalho em prompts menores.

Worktree sujo

Sintoma: falha informando que já existe um worktree no caminho, que a branch já existe, ou que há alterações não commitadas.

O OrqPEG não limpa e não descarta nada — essa é a garantia central do produto. A decisão é sua, com plena consciência:

cd /d E:\AI-Worktrees\meu-projeto\orqpeg-meu-projeto-run-20260721
git status
git stash list

Depois de salvar ou commitar o que interessa, remova o worktree pelo Git, sem forçar, ou habilite o reaproveitamento seguro na configuração do projeto. Nunca use limpeza ou reset destrutivo “por precaução”: eles apagam trabalho de forma irreversível.

Chave de API detectada no ambiente

Sintoma: a execução é bloqueada e o OrqPEG lista os nomes das variáveis presentes.

É a guarda de zero API funcionando. Você pode confirmar a continuação — o processo filho roda com ambiente sanitizado e a sua sessão do Windows permanece intacta — ou remover a variável da sessão, se ela não for necessária. O valor nunca é lido, gravado ou impresso.

Testes do projeto falhando na execução

Sintoma: o veredito do revisor volta pedindo mudanças por causa de teste vermelho.

Isso é o fluxo normal: uma nova tentativa é aberta com as ações exigidas, até o máximo configurado em execution.maxAttemptsPerPrompt. A saída completa de cada comando fica nos artefatos da tentativa. Se o limite for atingido, o prompt fica marcado como não aprovado e nada é commitado.
